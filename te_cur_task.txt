## 2. Что нужно сделать, чтобы T6-T11 реально заработали

Текущая модель: Gboard вводит через `commitText` по одному символу (НЕ composing).
Для candidate window, автокоррекции и preedit IME необходима composing-модель:
- Gboard должен слать `setComposingText` (composing), а не `commitText`
- нужно "держать" composing-регион и отправлять его обратно IME через `updateSelection`

Это **отдельная крупная задача**, не входит в текущий скоуп.

## 3. Тесты — ВСЕ ЗАПУСКАЮТСЯ (было dead code!)

### Проблема (исправлена)
`event.rs`, `input.rs`, `input_processing.rs` — под `#![cfg(target_os = "android")]`.
Мои тесты IME в `input_processing.rs` были **dead code** — никогда не запускались на хосте.

### Решение (рефакторинг)
Вынесена чистая IME-логика в **`crates/platform-android/src/ime_logic.rs`** (без `cfg(android)`):
- `ImeCmd` (переехал из `event.rs`)
- `ImeOutcome`, `ImeBuffer`, `process_ime_cmd`, `utf16_offset_to_char_index`
- `event.rs` теперь `pub use crate::ime_logic::ImeCmd`
- `input_processing.rs` делегирует в `ime_logic`

### Результат
`cargo test --workspace --lib` → **21 тест в platform-android** (было 7), **всего 134**:
```
25 (ui) + 28 (runtime) + 21 (platform-android: 7 platform_state + 14 ime_logic)
+ 23 (navigation) + 13 (core) + 24 (showcase) = 134  ✅
```

### Новые тесты (`ime_logic::tests`) — все запускаются на хосте
- `utf16_offset_bmp_chars_match` — BMP: offset == char index
- `utf16_offset_zero_always_zero` — offset 0 → 0 даже для эмодзи
- `utf16_offset_beyond_text_maps_to_len` — offset за пределами → длина
- `utf16_offset_emoji_reduces_char_index` — non-BMP: char < utf16 offset
- `commit_goes_directly_to_pending_without_batch`
- `delete_surrounding_before_emits_backspaces` / `after_emits_deletes`
- `batch_edit_buffers_and_flushes` — batch буферизует и выгружает
- `nested_batch_flushes_only_at_depth_zero` — вложенность
- `composing_sets_active_range_to_full_text` / `empty_composing_resets_active_range`
- `next_returns_next_outcome` / `done_returns_done_outcome`
- `set_selection_is_noop`
