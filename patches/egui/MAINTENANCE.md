# Обслуживание патча egui

> **Кратко:** этот документ — инвентарь всех локальных правок egui 0.35.0
> (форк в `patches/egui`) и план их снятия при апгрейде. Правило:
> **ни одна правка не считается «случайной»** — каждая решает конкретный
> баг с устройства и обязана иметь регресс-тест, защищающий её от повтора.

---

## Как устроен патч

Патч подключается в корневом `Cargo.toml` через:

```toml
[patch.crates-io]
egui = { path = "patches/egui" }
```

`patches/egui` — это **локальная копия зависимости egui** (`egui 0.35.0`),
содержащая исходники + наши правки поверх. Детали появления см. в
`patches/egui/PATCH_NOTES.md`.

### Важно про правки из `PATCH_NOTES.md`

`PATCH_NOTES.md` — **исторический журнал**, куда записывали, *когда и почему*
делалась правка. Часть записей со временем устарела относительно текущего кода
(например, блок «platform-android батчинг» в `run.rs` — см. секцию
«Откат бэкендового батчинга»). Он полезен для
понимания мотивации, но НЕ является точным списком того, что живёт в коде сейчас.

**Точный, актуальный список живых правок держим здесь** (этот файл).

## Инвентарь правок

| # | Модуль в патче | Суть правки | Решает баг | Регресс-тест |
|---|---|---|---|---|
| 1 | `src/input_state/mod.rs` | В `PointerState::begin_pass`: на кадре нового нажатия `old_pos = latest_pos` → `pointer.delta() == 0` | Скачок `ScrollArea` на 100–200pt при повторном тапе после fling | `scroll_jump_no_firstframe_jump` (в `input_state`) |
| 2 | `src/containers/scroll_area.rs` | При новых `drag_started()` сбрасывать остаточную `state.vel` (инерция от предыдущего fling) | Тот же скачок из-за наложенной скорости | ⛔ host-теста нет (в тестовом окружении `ScrollArea.dragged()` не срабатывает) — проверять на устройстве |
| 3 | `src/data/input/ime_event.rs` | Расширено `ImeEvent::Preedit` полем `replace_range` (custom, нет в апстриме) | Gboard `setComposingRegion`: preedit должен ЗАМЕНЯТЬ фрагмент, а не вставлять (иначе дубль «ппр») | `preedit_replace_range_then_insert_appends_not_overwrites` (в `crates/ui`) |
| 4 | `src/widgets/text_edit/builder.rs` | Ветка `Preedit` с `replace_range` возвращает каретку в конец (`one(ccursor)`), а не выделение диапазона | «привет как дела» — новое слово затирало предыдущее | тот же тест, что в #3 |
| 5 | `src/style.rs` | `default_legacy_visuals()` = true и на Android | Каретка/выделение не рисуются при активном предикте (нет мигающей каретки) | ⛔ device-тест `ime_caret_visible_uses_legacy_visuals` (в `examples/showcase/src/ime_tests.rs`), host-нет |

### Связность правок

- **#3 + #4 — одна фича IME** и должны сниматься/жить вместе: `replace_range`
  в типе и его потребление в `TextEditState::load`. Любой из них отдельно
  ломает ввод.
- **#1 + #2 — одна фича «scroll-jump»**, но защищают разные фазы:
  - `#1` устраняет **корень** — ложный `delta` на первом кадре нового драга;
  - `#2` — **вторичная защита** — гасит наложенную инерцию в самом
    `ScrollArea`. Корень может вернуться (апгрейд egui уберёт #1) раньше, чем
    #2 перестанет быть нужным, поэтому обе держим, пока жив хотя бы один
    пользовательский сценарий флинга на тач.
- **#1, #2 не зависят от #3–#5** и наоборот — можно снимать группами.

## Как проверить каждую правку (host)

```sh
# input_state — юнит-регресс живёт прямо в патче
cargo test -p egui input_state::scroll_jump_no_firstframe_jump

# replace_range — интеграционный тест в крейте UI (host)
cargo test -p egui-android-ui preedit_replace_range_then_insert_appends_not_overwrites
```

> Правка **#2** (сброс `state.vel` в `scroll_area.rs`) регресс-тестом на хосте
> **не покрыта** — см. §«Инвентарь правок». Проверяется вручную на устройстве
> (секция «На устройстве»).
>
> `legacy_visuals` на хосте проверить нельзя (зависит от `target_os`), см.
> секцию «На устройстве».

## План апгрейда egui

Перед обновлением `patches/egui` до новой версии апстрима:

1. **Сверь инвентарь (§ «Инвентарь правок»)** — какие из 5 правок уже есть в
   новой версии апстрима, какие нет.
2. **Сними снятые** правки из патча и обнови `PATCH_NOTES.md` (переноси историю,
   но живые правки оставляй в этом файле).
3. **Для оставшихся** — перебазируй дифф правок на новую версию.
4. **После перебазы обязательно**:
   ```sh
   cargo check --workspace
   cargo test -p egui
   cargo test -p egui-android-ui
   ```
   Ломаться (RED) должны только те регресс-тесты, чья правка ещё не внесена
   — это нормально, они и есть селектор «что починить на новой версии».
5. **На устройстве** прогони сценарии (секция «На устройстве»): ввод «привет как
   дела», мигающая каретка, скролл после флинга.
6. **Сними `[patch.crates-io] egui`** из корневого `Cargo.toml` и удали
   `patches/egui` **только когда** все живые правки попали в апстрим (или
   заменены его API).

### Откат бэкендового бейтринга (историческая правка)

PATCH_NOTES упоминает, что ранее часть fix scroll-jump жила и в
`crates/platform-android` (по фрейму с Down попадал только
`PointerButton { pressed: true }`, Move откладывались). **В актуальном коде
этого механизма уже нет** — `platform-android/src/input.rs` и
`loop.rs` пушат события напрямую. При апгрейде сверяться с этим разделом
PATCH_NOTES не нужно; проверяй по фактическому коду (§ «сверь инвентарь»).

## Почему мы не можем просто убрать патч

1. **`replace_range` вне апстрима.** Без него IME-ввод ломается в принципе
   (Gboard работают через `setComposingRegion`). Это самая связанная правка —
   и самая дорогая при апгрейде.
2. **Scroll-jump** — баг тач-скролла, ловится вручную на устройстве. Корневой
   фикс (`#1`, `delta==0`) закрыт host-регрессом; вторичная защита (`#2`) host-
   тестом не покрыта — проверяется на устройстве.
3. `legacy_visuals` — мелкий, но без него каретка «мертвеет» при предикте.

Удаление патча — **не** «подчистка», а отдельная задача: сначала убедиться,
что апстрим покрывает все 5 (или 3 IME-связанных) сценариев.

## На устройстве (когда host-тестов мало)

Файлы регресс-сценариев:
- **IME:** набрать «привет как дела» без потери и «каши»; убедиться, что
  каретка мигает при активном предикте и новое слово дописывает, а не затирает.
- **Scroll:** сделать fling вниз, дать остановиться, снова коснуться и
  протащить — не должно быть скачка offset (100–200pt) в первый кадр.

Каждый замеченный на устройстве баг → **сначала регресс-тест, потом фикс**
(см. правила TDD в `.agents/skills`).
